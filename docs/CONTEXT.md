# MyGitNotes 領域詞彙

## MyGitNotes 與儲存來源

MyGitNotes 是以 Git 保存的個人筆記與文件工作區。平台指 GitHub 或 GitLab；站台指平台所在的服務網址；儲存庫是筆記的來源。每個部署指定主儲存庫的平台、站台、儲存庫與分支；筆記本可以另外指定自己的筆記本儲存庫。一次寫入只落在一個儲存庫。GitLab.com 與自架 GitLab 使用相同的工作區操作。

### 用語

**主儲存庫**：部署設定指定的儲存庫，保存工作區設定。沒有指定儲存庫的筆記本，內容也放在這裡。避免稱為：預設 repo、home repo。

**筆記本儲存庫**：一個筆記本的內容所在的儲存庫。一個筆記本只屬於一個儲存庫；筆記本儲存庫只放工作區內容，沒有 `core`。避免稱為：外部 repo、子 repo。

**儲存庫 manifest**：每個儲存庫自己的 `.mygitnotes.yaml`，決定這個儲存庫的標題（標頭、筆記本切換器分組、Changes 與 Agents 頁顯示的名稱）、開啟時的預設筆記本，以及它的筆記本使用的偏好設定。沒有 manifest 的儲存庫以儲存庫名稱顯示。筆記本儲存庫提供哪些筆記本，目前仍由主儲存庫 manifest 的 `source` 決定。

## Core 與工作區分支

同一個儲存庫以兩條分支分開產品與內容。`core` 只放產品原始碼，工作區只從 upstream fast-forward 它；`main` 只放工作區內容，不再合併 `core`。兩者各自 checkout 在自己的 worktree，local server 從 core worktree 執行並編輯 main worktree。

### 用語

**Core**：產品原始碼所在的 `core` 分支與其 worktree。避免稱為：上游分支（upstream 指 remote）。

**工作區內容**：`main` 上的 `.mygitnotes.yaml`、筆記本根目錄、素材與工作區 Agent 設定。避免稱為：使用者分支。

**fork 模型工作區**：分離前建立、`main` 仍帶著產品程式碼的舊工作區；以 `convert-workspace` 轉換一次。

**轉換**：以一個 commit 移除 fork 模型 `main` 上的產品路徑，使它只放工作區內容；不改寫歷史，之後不再合併 Core。

**產品參考**：Core 的 `docs/agent/**`，在 Agents 頁唯讀顯示，不屬於工作區。

## Agent 工作區

Agent 工作區是 Pi 工作的資料夾，由資料夾決定範圍。每個儲存庫的根目錄一定是 Agent 工作區；筆記本根目錄、它的上層，或筆記本內的資料夾放了 `AGENTS.md` 也成為工作區。Agents 頁與 Agent 窗格都以工作區為單位。

### 用語

**Agent 工作區**：一個儲存庫裡的資料夾，帶著自己的核心指示與技能；Pi 在其中執行時，也套用外層工作區的核心指示與技能。避免稱為：agent system、執行目錄。

**核心指示**：工作區資料夾的 `AGENTS.md`。避免稱為：工作區共用、系統指令、CLAUDE.md（Claude 專用副本）。

**skill（技能）**：`<工作區>/.agents/skills/<name>/` 裡以 `SKILL.md` 為入口的指令，附帶參考資料（`scripts/` 以外的 Markdown 或文字檔）與腳本（`scripts/` 內的文字檔），名稱等於資料夾名。避免稱為：`.claude/skills`（客戶端專用副本）。

**MCP 伺服器設定**：Pi 連線的 MCP 伺服器。可能帶 token，從不放進儲存庫；社群版在 Pi 裡設定，Pro 版存在伺服器的加密紀錄。

MCP 的 `get_system_prompt`、`list_skills` 與 `invoke_skill` 照舊從目標資料夾往上讀每一層的 `AGENTS.md` 與 `.agents/skills`。

## 工作區呈現

合輯是筆記本內一份像筆記的檔案 `<名稱>.compilation.yml`，把內容集合成可閱讀、可學習的整體。
合輯屬於路徑所在的筆記本，可以收同一儲存庫裡任何筆記本的內容；項目以儲存庫相對路徑記錄，所屬筆記本由路徑所在的資料夾決定，不收其他儲存庫的內容。
路徑不在儲存庫任何筆記本內的項目顯示為找不到；動態合輯的資料夾來源必須在某個筆記本內，標籤來源只看合輯自己的筆記本。
關聯圖排列只畫合輯自己筆記本的成員，並提示另有幾個項目在其他筆記本。
自訂合輯持有項目參照；動態合輯持有 tag 或 folder 查詢。
合輯有三種排列：河道（水平卡片，縮圖、小、中版型）、書本（左側目錄，項目依序鋪成區段並連續捲動）、關聯圖。
書本有兩種閱讀方式：連續捲動（預設）與分頁（一次一章，資料夾章節算一頁）；選擇只記在目前瀏覽器，不寫進合輯檔案。
自訂合輯可以分章：項目清單裡的章名（`kind: heading`）開始一章，收它之後、下一個章名之前的項目，這些項目是該章的節；第一個章名之前的項目各自成章。書本目錄列出章與節，分頁時一章一頁；河道把章名畫成分隔欄。動態合輯以 `group: folder` 依資料夾分章。
河道的卡片與書本的筆記區段都能就地編輯：點內文或「編輯」，卡片或區段就變成該筆記的編輯器，同一時間只有一處在編輯；點標題仍在放大檢視中開啟同一個編輯狀態。
編輯時維持閱讀時的版面：沒有分頁、紙面、工具列與底部狀態列，只多一行存檔狀態；原始碼模式、大綱與屬性到放大檢視使用。
合輯寬度不到 560px（分割的 Focus 窗格、手機）時，河道的卡片改為由上往下排成一欄，寬度跟著合輯，高度仍依縮圖、小、中而定。
學習用獨立按鈕進入學習頁；需要修改筆記時開啟原本編輯器。

合輯不擁有原始資料。
取消釘選或刪除合輯不刪除筆記、資料夾、資源。
動態內容不可拖入或拖出，只有自訂項目支援同一合輯內與跨合輯拖曳。

合輯檔隨筆記本內容一起放在 Git，跟著筆記搬移與同步；搬移或重新命名筆記與資料夾時，合輯內的參照一併更新。
舊版 `.github-notes-screen.yaml`（Screen Page）已由 `pnpm migrate-workspace` 轉成合輯檔並刪除。
本機草稿只是尚未儲存的恢復副本，不代表合輯已同步。

筆記本可以替每個狀態設定顯示名稱（`label`），依介面語言顯示，沒有就退回狀態的 `name`。筆記 frontmatter 的 `status:` 只存 `name`，不受介面語言影響；預設的四個狀態沒有 label 時在繁體中文介面顯示內建名稱，英文介面顯示儲存的名稱。多個筆記本的 label 依語言合併，同一語言由先給出的筆記本決定。

## 專案任務

任務行、負責人、優先順序與里程碑都是筆記裡的純文字，沒有額外儲存；沒用到的筆記不受影響，勾選任務只增減 `✅`，其他標記原樣保留。解析在 core（`@mygitnotes/core/task-tokens`、`note-agenda`），呈現在 web 的待辦事項、甘特圖與行事曆。

### 用語

- **負責人（assignee）**：任務行裡的 `@名字`。`@` 在任務文字開頭或空白之後，名字由字母、數字與 `_` 組成，`.` 或 `-` 只能夾在名字字元之間（`@alice`、`@小林`、`@j.doe`）；可以有多位，重複只算一次，大小寫視為不同。email、網址與套件名（`a@b.com`、`https://x.com/@u`、`@types/node`）不算，名字後的句號與逗號不屬於名字。
- **優先順序（priority）**：任務行任何位置的 Obsidian Tasks 表情符號：`🔺` 最高、`⏫` 高、`🔼` 中、`🔽` 低、`⏬` 最低；沒有符號是「一般」，排序時介於中與低之間；一行有多個時取第一個。
- **里程碑（milestone）**：frontmatter 的 `milestone: YYYY-MM-DD`，必須是真實日期的字串，其他值不算。它是筆記的屬性，不是任務；`due` 不借用，因為 `due` 已是任務 `📅` 到期日與學習排程的用語。
- **待辦事項工具**：每個任務顯示負責人與優先順序；「負責人」篩選（所有人、範圍內每位負責人、未指派）、「優先順序」篩選與「排序」（清單順序、依優先順序）套用到依日期、依筆記與甘特圖。里程碑不是任務，不受這些篩選影響，只出現在甘特圖與行事曆。
- **甘特圖**：長條依優先順序上色；每個里程碑在自己的列畫一個菱形，帶筆記標題，點擊開啟筆記，日期範圍也涵蓋里程碑。
- **行事曆**：里程碑在當天以菱形標示，當天詳情的「里程碑」區列出筆記；不受「建立／更新」切換影響。

## 排版預覽

本機工作區可以在 Markdown 筆記旁邊顯示 thesis-toolkit 專案排好的 PDF。Markdown 是唯一的原稿，編譯時才由範本轉成 Typst；預覽只在本機模式提供，遠端工作區沒有。

### 用語

**排版預覽（Typst preview）**：頁面與 Agent 窗格之間的一欄，顯示目前筆記所屬編譯專案的 PDF。開啟時、專案內的筆記每次存到本機後、按「重新編譯」時各編譯一次；新版本換上時留在原來那一頁的同一個位置，編譯失敗時保留上一次成功的頁面。PDF 寫在伺服器的暫存資料夾，不進工作區。避免稱為：PDF 模式、Typst 模式。

**編譯專案**：`thesis-toolkit.json` 的 `projectsDir` 底下的一個資料夾，裡面的 `src/<目標>/main.typ` 各是一個編譯目標。筆記在哪個專案，由它上層最近的 `thesis-toolkit.json` 決定；不在任何專案裡的筆記沒有排版預覽。避免稱為：Typst 專案（沒有通用的 Typst 設定，只認 thesis-toolkit）。

**編譯目標**：編譯專案 `src/` 底下帶 `main.typ` 的資料夾，例如 `main`；有 `main` 時預設用它。

**引註**：編譯專案的筆記裡的 Pandoc 引註：`[@key]`、`[@a; @b, 23]`、只印年份的 `[-@key]`，以及敘述式的 `@key`。即時編輯器在游標離開那一行後，把引註顯示成預設格式會印出的樣子，例如 `(Sosa 2007)`，檔案文字不變；key 不在書目裡時保留原文並加虛線底線。寫法以 thesis-toolkit 的 zh-journal 範本為準。任務行裡的 `@名字` 仍是負責人，不是引註。

## 關聯圖與合輯（已確認方向，待實作）

### 用語

**合輯**：由自訂項目參照或動態查詢界定的內容集合，存成筆記本內的 `*.compilation.yml`，可以用不同排列顯示；項目可來自同一儲存庫的任何筆記本。避免稱為：Screen、泳道。

**河道**：合輯的一種排列，水平卡片列。不再指整個內容集合。

**書本**：合輯的一種排列，左側目錄加上整份合輯連續捲動的內文，項目依序成為章節，資料夾的筆記成為其下的小節，筆記區段可就地編輯。有章名時，章名成為章，其下的項目成為節。取代舊稱「拼接」與「堆疊」（檔案裡的舊值 `stack` 仍讀成書本）。避免稱為：拼接、堆疊。

**書本分頁模式**：書本的閱讀方式之一，一次顯示一章，用上一頁／下一頁、← →、觸控左右滑動或目錄換頁；離開正在編輯的頁面前先儲存。選擇存在瀏覽器（每台裝置），不屬於合輯內容。與筆記內以 `---` 分隔的線性頁面不同；避免稱為：翻頁模式、分頁排列。

**章（chapter）**：自訂合輯裡由章名（檔案中的 `kind: heading` 項目）開始的一組項目，到下一個章名為止；只有一層，沒有小章。檔案仍叫 `heading`，介面稱「章」。避免稱為：段落、分組。

**節（section）**：章名之下的項目。資料夾項目在章下仍列出自己的筆記，成為再下一層。

**依資料夾分章**：動態合輯的 `group: folder`，每個有成員的資料夾成為一章，章名取資料夾標題（多層以「 / 」連接），順序依側欄的資料夾順序，資料夾來源本身的筆記排在最前。章只存在於瀏覽器，不寫進檔案。

**筆記的一段**：帶 `anchor` 的筆記項目，只顯示筆記中該標題到下一個同級或更高級標題之間的內容。標題比對與 `#標題` 連結相同，同名時取第一個；標題改名後項目顯示找不到，不會自動改寫。編輯時在放大檢視開啟整篇筆記並捲到該標題，不在合輯裡就地編輯。

**就地編輯**：在合輯的卡片或書本區段內直接編輯筆記，不離開合輯；用的是同一個筆記編輯器與同一份草稿，沒有另一條儲存路徑。

**關聯圖檢視**：由指定筆記集合及其內容連結形成的空間呈現。合輯可以作為它的內容範圍，也可以直接使用關聯圖排列。

**筆記節點**：筆記在關聯圖中的同一個物件，可以收合為節點或展開為可編輯筆記。展開不建立另一份筆記，多選與展開是不同操作。

使用者可將關聯圖內多選的筆記存成合輯，再由合輯開啟關聯圖。合輯持有筆記參照，正文與連結仍由原筆記擁有；移除合輯或收合節點不刪除原筆記。

## Focus 與 zoom（已確認方向，待實作）

Notes 的瀏覽區顯示篩選結果；Focus 顯示時，瀏覽區讓出空間停靠在旁，點選的筆記開進 Focus。zoom 是單一筆記的全螢幕編輯畫面，一般瀏覽時點選筆記就進入 zoom。

### 用語

**Focus**：屬於單一筆記本的一組窗格，窗格排成一棵分割樹，窗格內的 tab 參照該筆記本的筆記或河道。Focus 只持有參照，移除 tab 或刪除 Focus 不刪除內容。避免稱為：窗格模式、notes tiles、工作區。

**預設**：每個筆記本唯一的未命名 Focus，用來隨手開啟筆記，筆記頁一定顯示一個 Focus，沒有指定時顯示它。命名後成為具名 Focus，預設回到空白；刪除具名 Focus 則回到預設。預設 Focus 不能關閉，只能清除：清成單一空窗格，立即清除不確認；具名 Focus 可以關閉（改顯示預設），也可以清除，清除先確認。英文介面稱 Default。避免稱為：暫存、Scratch、(current)（程式內代稱，見 `CURRENT_FOCUS`）。

**分割**：把一個窗格切成兩個窗格，新窗格開在上、下、左或右一側。把筆記或 tab 拖到窗格邊緣，或從窗格 tab 列右端的窗格動作選單選向右分割、向下分割，就會分割；合併所有窗格把全部窗格併回一個。關閉窗格的最後一個 tab，那個窗格就移除，鄰近窗格接手它的空間。一個 Focus 最多 8 個窗格、巢狀 4 層分割。避免稱為：劃分（舊版固定七種排列，已取消）。

**窗格配置**：Focus 的窗格如何分割排列，只在需要指稱整體時用。避免稱為：劃分、版型（已指河道卡片大小）、layout。

**窗格**：分割後的一格，持有一個以上的 tab，同時顯示其中一個。避免稱為：tile、面板（已指文件面板與右側工具）。

**作用窗格**：Focus 中接收開啟動作的窗格，同時只有一個。避免稱為：焦點格、目前格。

**tab**：窗格內對一則筆記或一條河道的參照。同一則筆記在一個窗格裡只有一個 tab，在不同窗格可以各有一個。避免稱為：分頁（已指筆記的線性頁面）。

**zoom**：單一筆記的全螢幕編輯畫面，關閉後回到進入前的畫面。直接打開的筆記網址會開進 Focus，網址加上 `?zoom` 則直接進入 zoom，關閉後回到筆記本。避免稱為：全屏 dialog、編輯器 modal。

**Focus 的網址**：Focus 顯示時，網址跟著作用窗格的筆記，是那則筆記的筆記網址，保留瀏覽區的篩選與 `focus` 參數，可以直接複製給別人或重新整理；作用窗格顯示河道、或 Focus 是空的，網址就是筆記本。開啟筆記（點清單、點連結、打開網址）新增一筆瀏覽紀錄；切換 tab 或窗格、關閉 tab、重新命名只更換目前這筆。上一頁回到前一則筆記時，選回它原本的 tab，不另開一個。手機在筆記畫面時一樣，回到清單畫面就是筆記本的網址。別的筆記本的筆記與範本仍進 zoom，zoom 的網址不變。

**編輯模式**：zoom 與 Focus 窗格的筆記編輯器怎麼顯示 Markdown 筆記：即時預覽、原始碼或分割檢視，由筆記標題列的三個模式按鈕切換（手機的「⋯」選單只在即時預覽與原始碼之間切換）。目前的模式寫在網址的 `?mode=`（`source`、`split`）；即時預覽是預設，不寫進網址，網址沒有 `mode` 就是即時預覽。切換模式只更換目前這筆瀏覽紀錄，保留其他參數與 `#`，所以重新整理或分享網址會開回同一個模式。關聯圖卡片與 Agent 系統頁保留自己的兩種模式，不看網址。避免稱為：檢視模式（已指瀏覽區的 list、card 等）、raw 模式（程式內代稱）。

**閱讀與編輯（手機）**：手機打開筆記一律先閱讀，內文不能改，長按只選取文字，不會叫出鍵盤把畫面推走。按標題列的「編輯」或在內文上點兩下才切到編輯，按「完成」回到閱讀。點兩下時，游標落在第二下點到的字旁，鍵盤直接出現。點兩下的位置若在連結、勾選框、按鈕、圖片上，或在表格、指令區塊、資訊圖表、圖片標註這類自己處理點擊的區塊裡，就不切換，交給它們處理。不能編輯的筆記（唯讀、沒有權限、正在處理衝突）沒有「編輯」，點兩下也不切換。即時編輯儲存庫裡還沒簽出的筆記，點兩下等於按「編輯」：簽出後才開啟即時編輯器，要再點一下內文才有鍵盤。比手機寬的畫面不分閱讀與編輯，即時編輯器也沒有閱讀狀態：筆記簽出、即時編輯器開著時，標題列不出現「編輯」或「完成」，要結束就用即時編輯器自己的「立即簽回」或「關閉」。避免稱為：唯讀模式、預覽模式。

**分割檢視（split view）**：左邊是原始碼編輯器，右邊是用閱讀時同一套轉譯畫出的筆記（指令區塊、數學、mermaid、圖示都有），停止打字片刻後更新。左邊鋪頁面底色、右邊鋪表面色，一眼分得出哪邊在打字；原始碼比窗格長時在左邊自己捲動。中間分隔線上的按鈕切換同步捲動，預設連動，選擇記在這次瀏覽工作階段，不寫進網址；連動時任一邊捲動，另一邊依「原始碼的行對應到它開始的轉譯區塊」捲到同一處。只在 zoom 且比手機寬的畫面顯示：Focus 窗格選分割檢視會把那則筆記開進 zoom（新增一筆瀏覽紀錄，上一頁回到原本的 Focus 與 tab）；手機或 Focus 窗格遇到 `?mode=split` 的網址改顯示即時預覽，網址不變。避免稱為：雙欄模式、預覽模式。

**清單篩選**：每本筆記本在這台裝置各自記住標籤與比對方式、狀態、即時編輯狀態、是否顯示隱藏筆記、是否依資料夾分組、文件種類，以及是否包含子資料夾。
回到筆記本時沿用上次的選擇；網址只要指定了其中一項，就以網址為準，不補上其他條件。搜尋文字不記錄；按「清除篩選」也會清除這本筆記本記住的條件。

**瀏覽區**：顯示 Notes 篩選結果的 list、flat、kanban 區域（舊網址的 card 以 list 顯示）。Focus 顯示筆記時，list、flat 停靠左側；kanban 看 Focus 有幾個窗格：只有一個時，看板留在左邊、Focus 在右側並排（見「看板並排」）；兩個以上，或按了「開進 Focus」，看板收進左側停靠欄，變成狀態分組清單。手機不分這兩種，看板與筆記照舊輪流佔滿畫面。避免稱為：筆記欄、notes list pane。

**看板並排**：kanban 遇到只有一個窗格的 Focus 時的版面。看板在左、保有整個高度，Focus 在右側；中間的分隔線可以拖曳，或用左右方向鍵、Home、End 調整，看板佔的寬度記在這台裝置（舊版看板疊在 Focus 上方時記的高度不再沿用）。點卡片就把筆記開進作用窗格，看板不動，開著的那張卡片加框標出；卡片照樣可以拖到別欄改狀態，或拖進 Focus 的窗格。Focus 左上角的「開進 Focus」把看板收成狀態分組清單，讓 Focus 佔滿右邊。避免稱為：看板上下分割（舊版版面，已取消）、side panel。

**狀態分組清單**：看板收進左側停靠欄後的樣子。看板的每一欄變成一個可收合的群組，照看板的欄序排，無狀態排最後（沒有無狀態的筆記就不出現）。群組標題是狀態色點、名稱與篇數，每一列是筆記標題與更新日期；每組先列 5 則，其餘按「還有 N 則」再展開，作用窗格開著的那則一定列出。把一列拖到別的群組（收合的群組也可以）就改成那個狀態，規則和看板相同：編輯中、前置資料讀不出來的筆記不能改狀態，但可以拖進 Focus 的窗格。各群組收合與否記在這台裝置。清單欄頂的「展開看板」回到看板並排。Focus 有兩個以上的窗格時看板一直收著，這個按鈕只用提示說明原因，把窗格合併成一個以後，看板回到使用者上次留下的樣子。按「開進 Focus」的選擇重新整理後仍在；Focus 沒有筆記、看板回到整頁時就取消，下次點卡片又是看板並排。避免稱為：看板清單模式、fold list。

**窄條**：看板上收起來的欄，約 30px 寬，直排顯示狀態色點、名稱與篇數。沒有筆記的欄預設是窄條；任何一欄都能按欄頂的收合按鈕收成窄條，點窄條就展開。窄條照樣可以接住拖過來的卡片。每一欄收起或展開，記在這台裝置。欄寬隨看板可用的寬度在 180px 到 320px 之間伸縮，再窄就讓看板左右捲動；欄寬不到約 240px 時，欄自己的排序選單與卡片上的左右移動箭頭先收起來，排序改用看板的，移欄改用拖曳。避免稱為：摺疊欄、mini column。

**卡片密度**：看板工具列的「精簡／一般」切換，記在這台裝置。一般是完整的卡片：標題、標籤、日期與按鈕。精簡只留一行標題，下面一行是「#第一個標籤 · 日期」，按鈕要等滑鼠停在卡片上、或鍵盤移到卡片裡才出現（觸控裝置一直顯示）。無狀態欄的卡片本來就簡短，不分密度。避免稱為：緊湊模式、卡片大小（已指河道卡片的版型）。

**頂列**：每一頁最上面那一列，左起是工作區名稱、頁面切換鈕（筆記、關聯圖、檔案、設定），右端是筆記本選單、Agent 與快速開啟按鈕。在筆記頁，筆記本選單左邊多了 Focus 選單與窗格配置，右邊多了新增按鈕（唯讀的筆記本沒有新增）；其他頁沒有這兩組。頂列放不下時依序收起：新增只剩 ＋ 圖示，筆記本選單變窄、名稱截斷，Focus 選單只剩圖示（名稱在滑鼠提示裡）；頁面切換鈕一直保留文字。視窗 1160px 以下，頂列分成兩列，頁面切換鈕在第二列。手機的筆記頁沒有頂列，只有底部的頁面切換。避免稱為：header、標頭列。

**筆記工具列**：筆記頁頂列下面的那一列，左邊是清單工具（搜尋、排序、顯示隱藏筆記、依資料夾分組），右端是清單、資料夾、看板三個檢視按鈕。沒打開筆記時、以及看板與 Focus 並排時才有；list、flat 停靠左側，或看板收成狀態分組清單時，沒有這一列（見「左側停靠欄」）。

**左側停靠欄**：Focus 顯示時，list、flat 瀏覽區停靠的那一欄，底色和側欄相同；看板收起時，狀態分組清單也放在這一欄，欄頂多一個「展開看板」。由上而下是：清單工具列（搜尋、排序、顯示隱藏筆記、依資料夾分組，行尾是切換清單、資料夾、看板的檢視選單），目前的路徑和篇數（行尾是收合停靠欄的按鈕），清單，再來是分隔線，分隔線下面是目錄（資料夾樹，以及狀態、即時編輯與標籤 chip、版本加的連結）。分隔線可以拖曳或用方向鍵調整，目錄也可以收成只剩欄底的標題列；目錄的高度與收合狀態記在這台裝置的 Focus 檢視狀態裡（0.23.1 以前目錄在清單上面，當時設定的高度沿用，沒調過的預設值改成新的預設）。這時桌機的側欄收起，不再有圖示列，也沒有筆記工具列：停靠欄直接接在頂列下面，Focus、窗格配置與新增都在頂列。停靠欄收合時頂列也一起收起，只留一列工具列：左端是展開停靠欄的按鈕，正在搜尋的話還有一個搜尋按鈕，按下或用搜尋快捷鍵都會展開停靠欄並把游標放進搜尋框；右邊是 Focus、窗格配置、新增，以及頂列的 Agent 與快速開啟按鈕。看板與 Focus 並排或沒有 Focus 時，搜尋照常在筆記工具列，左邊照常是側欄。手機的清單畫面在 Focus 顯示時，搜尋在頂端那一列，篩選 chip 與清單在中間，資料夾樹在分隔線下面。一般瀏覽（沒有 Focus）時版面不變。避免稱為：圖示列、flyout、側欄窗格。

## 筆記範本

**範本（Template）**：新增筆記時套用的 Markdown 檔，放在筆記本根目錄的 `.templates/` 資料夾，檔名去掉 `.md` 就是範本的 id，不必登記就會出現在新增選單。`.mygitnotes.yaml` 的 `notebooks[].templates` 登記的範本照舊可用，排在前面，id 相同時以登記的為準。範本檔不是筆記，不會出現在筆記清單、搜尋與資料夾裡。避免稱為：模板、樣板。

**範本區塊**：範本前置資料裡的 `template:`，記錄範本的名稱（`name`）、說明（`description`）、新筆記的路徑樣式（`path`）和各預留位置的說明與預設值（`placeholders`）。建立筆記時不會複製這個區塊，其他前置資料欄位會照抄。用範本建立的筆記改記一行 `template: <範本 id>`，說明它出自哪個範本：`template:` 在範本檔裡是這個區塊，在筆記裡只是範本的 id，筆記不因此有任何不同。

**上次使用**：範本最近一次被拿來建立筆記的時間，取同一本筆記本裡帶 `template: <範本 id>` 的筆記中最新的 `created`（沒有就用 `updated`）。MCP 的 `list_templates` 依這個時間由新到舊排列，沒用過的排在後面，依名稱排序。

**預留位置（Placeholder）**：範本裡寫成 `{{名稱}}` 的位置。`title`、`date`、`time` 是內建的，建立筆記時自動填入；其他的先看呼叫端給的值，再看範本宣告的預設值，都沒有就原樣留下 `{{名稱}}`，讓寫的人知道還缺什麼。從新增選單建立筆記只填內建的三個，其餘留在編輯器裡改；MCP 的 `save_note` 用 `template` 與 `values` 逐一填入。避免稱為：變數、佔位符。

**管理範本**：新增選單最後一項，列出目前筆記本的範本，可以新增、編輯、重新命名、刪除。編輯範本就是在 zoom 裡用一般的筆記編輯器開啟範本檔，草稿與 Changes 都和筆記一樣，編輯器會標示「範本」；範本檔不會開進 Focus 的窗格。登記在 `.mygitnotes.yaml` 的範本只能編輯，內建範本（投影片）只列出。筆記的「⋯」選單可以把筆記**存成範本**。唯讀的筆記本不顯示新增按鈕與新增選單，所以沒有管理範本。

## 大綱筆記

**大綱筆記（Outline note）**是以 `*.outline.md` 副檔名辨識的 Markdown 筆記類型，介面簡稱「大綱／Outline」。
一個筆記本可以有多份各自具名的大綱，沿用一般筆記的身分、前置資料、編輯器、草稿與儲存流程。
**項目／節點**是一般清單項目，可包含文字、零個或多個連結、註記及任意層子項目。
**註記**是同一項目內沒有新清單標記的延續文字。
文字項目不代表資料夾，含連結的項目也可以有子項目。
書籤清單只是大綱的一種用途。

Enter 新增同層項目，Shift+Enter 新增同項註記，Tab／Shift+Tab 縮排或提升整個子樹；即時編輯器支援同份大綱內拖曳及單次復原。
所有操作修改同一份 Markdown，不另存可編輯樹狀資料或節點 ID。
「加入大綱」先選擇既有或新建的大綱，再於實際開啟的編輯器插入目前內容的普通連結。
內部連結與搬移以筆記本及儲存庫為範圍；不同儲存庫的相同路徑不是同一目標。
本機儲存、遠端瀏覽器草稿及 Git 提交維持不同狀態。

**舊書籤集合**指保留於 `.mygitnotes-bookmarks.yaml` 的相容資料，已退出一般編輯與變更流程。
顯式匯入可將筆記、合輯與 HTTP(S) 連結轉成新大綱，群組轉為文字父項目；精確位置、查詢與資料夾保留於來源並列出原因。
部分匯入必須確認，永不覆寫或刪除原始來源，也不重新指派未知擁有者。
瀏覽器舊草稿以完整原始資料匯出或明確捨棄，保留原基底與版本，不自動合併或儲存。
舊檔案的保護與受控搬移參照更新仍保留。

## 圖片標註

**圖片標註（Image annotation）**是筆記內容的一部分：`:::annotate` 區塊以第一行一般 Markdown 圖片加上每則標註一列組成。
標註是**標記點（pin）**或**框選區域（region）**，位置以圖片寬高的百分比表示，各帶一段 Markdown 留言、選填的 `by=` 作者與 `resolved` 旗標。
編號是顯示在標記上的 `#n`，新增取最大值加一，刪除不重編。
介面與 i18n 一律稱「圖片標註」（`imageAnnotation.*`），以免和大綱的**註記**（同一項目內的延續文字）混淆。
標註存在筆記文字裡，所以草稿、提交、版本歷程、示範模式與 AI 工具不需額外支援；編輯器的每個動作只改動該列。
格式有問題的列不會被丟掉，會連同原因顯示並原樣保留。
公開頁與列印以同一份靜態 HTML 顯示，不需遷移現有筆記。

**PDF 標註（PDF annotation）**是同一個 `:::annotate` 區塊，第一行改成行內連結 `[名稱](路徑)`，每一列多一個 `page=N`（從 1 起算的頁序，不是印在頁面上的頁碼）。
座標是該頁顯示（含頁面自己的 `/Rotate`）時寬高的百分比。
介面與 i18n 仍用 `imageAnnotation.*`。App 一次顯示一頁並按需載入 pdf.js；沒有文字層；公開頁在第 2c 階段前只列清單。

## 分頁與學習

正文頂層 `---` 將筆記分為線性頁面。一般閱讀仍以分隔線呈現；分頁閱讀依原始順序翻頁。學習卡以頁面對應定義題目與答案，每張卡有固定身分與獨立記憶排程。一份筆記可對應多張卡；反向卡與填空卡共用原始內容。

閱讀與回想事件分開記錄。學習流程以 note status 定義階段，熟悉程度控制前進或退回，複習間隔由目的階段決定。階段與間隔由學習頁的合輯編輯視窗配置；一般合輯保留原本操作。合輯引用同一份學習資料，移除項目保留學習紀錄。每個筆記本儲存庫根目錄的 `.github-notes-study.yaml` 保存該儲存庫內筆記本的卡片身分、階段、到期及事件，透過 Git 跨裝置同步。

閱讀／學習頁一次顯示一張卡片，題目及答案揭示後可來回翻頁，切卡不寫入評分。`/notes/study?notebook=<id>&path=<路徑>` 是合輯的專屬全螢幕學習頁，開啟時切換到合輯所屬筆記本，固定最早到期排序，保留操作與編輯器返回來源，與合輯排列分開。舊網址 `/screen/lanes/<id>` 會轉址到對應合輯的學習頁。學習紀錄以合輯的 `id` 為鍵，遷移後歷史不變。

上次移動時間是使用者最近一次成功提交熟悉程度的時間；忘記、吃力、記得、輕鬆皆算移動，保留原階段也重新計時。到期由該次移動時間加目的階段間隔決定。自訂延後調整到期，保留上次移動時間；撤銷還原前次時間。翻頁、切卡與略過屬於閱讀操作。

## 即時編輯器

部署可以把遠端儲存庫的筆記交給即時（共同）編輯器編輯。即時編輯器有兩種：版本（edition）框進來的外部編輯器，社群版只提供接口與規則，不指名任何特定編輯器；以及社群版自己附的內建即時編輯器：版本可以帶著自己的寫入憑證組裝，自架部署也可以用環境變數開啟，這時簽回用的是編輯者自己登入時存下的憑證。

### 用語

**即時編輯器（live editor）**：版本接到儲存庫上的共同編輯器，涵蓋框架即時編輯器與內建即時編輯器兩種。避免稱為：協作筆記。

**框架即時編輯器（framed live editor）**：App 以框架嵌入的外部即時編輯器（0.19）。

**內建即時編輯器（built-in live editor）**：社群版自己附的即時編輯器（0.20）：多人直接在 MyGitNotes 自己的編輯器裡共同編輯筆記。避免稱為：協作模式、Yjs 編輯器。

**簽出世代（epoch）**：一則連結從簽出或重新開啟到簽回之間的一次簽出。較早世代裡打的字，永遠不會進入較晚的世代。避免稱為：版本（筆記版本與 edition 都已用這個詞）。

**簽出（check out）**：把 Git 裡的筆記交給即時編輯器。從簽出到簽回之間，筆記目前的內容就是即時文字。避免稱為：鎖定、轉成即時筆記。

**簽回（check in）**：把即時文字提交到 Git，並關閉這則即時筆記。每晚自動執行一次，大家都離開之後也會閒置簽回，還可以按「立即簽回」。避免稱為：同步、歸檔。

**閒置簽回（idle check-in）**：一則即時筆記已經沒有人在編輯，而且距離最後一次編輯滿 5 分鐘（部署可用 `MYGITNOTES_LIVE_IDLE_CHECKIN` 調整或關閉）之後，自動執行的簽回。關掉分頁就算離開；分頁開著沒動，10 分鐘後也算離開。只看過、沒改過（或改了又復原）的筆記，最後一個人離開時就立刻釋放，不必等 5 分鐘，也不產生提交。

**編輯中（checked out）**：筆記在簽出與簽回之間的狀態。編輯器支援時可以移動或改名，下次簽回才搬過去（見「簽回後移動」）；其他檔案操作會被拒絕。

**簽回後移動（move at check-in）**：移動或改名編輯中的已歸檔筆記時，只記下目標路徑，不提交；清單把它列在目標位置，標「簽回後移到這裡」，舊網址轉到新位置，編輯照常進行。下次簽回以一個提交完成移動並改寫連結。沒有別人在編輯時當場簽回。簽回時目標已存在，筆記留在原處並標「沒有移動：目標已存在」；移動要改寫的檔案超過一次提交的上限時，筆記也留在原處，標「沒有移動：牽動的檔案太多」。移動資料夾時，編輯中的筆記留在原處等簽回再搬，指向它的連結也先指著原處，它自己指向同資料夾其他筆記的連結則立刻跟著改；沒能跟著移動的筆記會在移動完成後告知，仍留在原處。避免稱為：預約移動、延遲移動。

**編輯網址（edit link）**：筆記網址加上 `?edit`（也可以是 `?zoom&edit`，`edit` 帶不帶值都一樣），打開後等於在那則筆記上按「編輯」：進入 zoom 並簽出，從 Focus 窗格或手機打開也一樣會先進 zoom。協作優先的儲存庫本來就會在打開時簽出，所以 Focus 窗格與手機直接在原地打開協作編輯器，不另外進 zoom。簽出後網址拿掉 `edit`，其他參數與 `#` 照原樣保留，只更換目前這筆瀏覽紀錄，所以重新整理或上一頁不會再簽出一次。沒有權限寫入、沒登入或部署沒有即時編輯器時，筆記照一般方式顯示，網址保留 `edit`。外部應用程式用 MCP `save_note` 建立筆記後，可以存這個網址，讓人點開就直接共同編輯。避免稱為：簽出連結、即時編輯模式。

**協作優先（collab-first）**：使用內建即時編輯器的儲存庫，伺服器連得上時，可寫入的人打開筆記（zoom、Focus 窗格、手機）就直接進協作編輯器並簽出，不必先按「編輯」；連不上時改開直接編輯器，修改先存成這台裝置上的草稿。只看過就離開的筆記，最後一個人離開時就立刻釋放、不提交，清單上不顯示「編輯中」，也不擋移動、重新命名、刪除和批次操作。從協作編輯器移動或重新命名筆記時，筆記照常開著，簽回後才移動（見「簽回後移動」）；刪除時只有自己在編輯才會先簽回再執行，還有別人在編輯就拒絕。避免稱為：協作模式。

**協作編輯器的標頭屬性（collab frontmatter）**：內建即時編輯器跟直接編輯器一樣只顯示本文：可解析的 frontmatter（含其後的空白分隔行）在編輯器裡隱藏，打字、全選刪除、貼上、Vim 都改不到它，別人或面板寫入的變更照常同步；YAML 無法解析時照原文顯示，修正後再隱藏；第一行是 `---`、卻沒有一行只有 `---` 來收尾（例如收尾寫成 `---x` 或 `----`）也算無法解析，筆記列會警告、表單鎖住，各個筆記清單也在狀態的位置標同一個警告，任何寫入都不會在它前面再加一個區塊。標頭屬性的 YAML 檢視跟著即時文字更新，只有打到一半、還沒寫出去的內容會留著。標題、狀態、標籤和其他欄位改在筆記列與文件面板的「標頭屬性」裡讀寫，直接寫進即時文字：只改有變的那個 key，其他 key、註解、順序和本文的位元組不動，也不蓋時間戳記；只在連線且同步時可以改。同一個欄位兩人同時改會串在一起（例如 `donereview`），看得到，改回即可。已歸檔筆記改標題會記下新檔名、簽回時改名（見「簽回後移動」），未歸檔筆記只寫 `title:`；資訊裡的 Gist 只能看，不能發佈或取消。文件面板每個分頁（尋找、大綱、標頭屬性與資訊、檢視、歷史）都讀即時文字；歷史的「還原」確認後把整份即時文字（含 frontmatter）換成那個版本。Live、Source、Split 與行號都能用：Source 與 Split 的原始碼編輯整份即時文字，包含 frontmatter。框架即時編輯器不變。

**離線接手（offline handover）**：在即時筆記與瀏覽器裡的草稿之間搬移文字，任一方向都不丟字。協作編輯器離線時打的字先存在瀏覽器（IndexedDB），重新整理後還在；連線後同一個簽出世代就直接同步，筆記若已簽回，就把這段文字以三方合併併入目前的筆記。離線時在直接編輯器寫的草稿、離線新增的筆記，連線後也自動併入（新筆記先建成未歸檔的即時筆記，文字一併帶入，簽回時照樣歸檔）。合併衝突時，草稿留著並提示，可以比對、複製或捨棄，由本人決定。避免稱為：離線同步。

**未歸檔的即時筆記（pending live note）**：在即時編輯器裡新增、還沒有 Git 路徑的筆記。第一次簽回時，依它的路徑規則歸檔到規則算出的路徑。編輯器支援時，可以先改它的歸檔資料夾或檔名（只改路徑規則，不提交），也可以捨棄。

**捨棄草稿（discard a draft）**：丟掉一則未歸檔的即時筆記與它的即時文字，不提交到 Git。已有 Git 路徑的筆記不能捨棄。

**空白草稿（empty draft）**：未歸檔的即時筆記，扣掉 frontmatter、建立時就有的那幾行（沒有建立時的文字時，扣掉新增筆記預設的標題與提示行）之後，只剩空白、標點、Markdown 符號或 emoji，沒有任何文字、數字、圖片或嵌入。編輯器支援捨棄時，空白草稿在簽回時會被捨棄，不會歸檔。
