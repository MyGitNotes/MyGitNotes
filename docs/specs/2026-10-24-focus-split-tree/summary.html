Focus 分割樹：設計摘要與待決事項

結論：Focus 的版面改成像 Obsidian 的分割樹。 把筆記或 tab 拖到窗格的上下左右邊緣就把該窗格切開；關掉窗格的最後一個 tab，窗格就收起來。 不再先選「左右、2×2」這類劃分。 設計分六個可以各自上線的 commit。 第一個 commit 只換資料模型，畫面幾乎不變；它要先部署到 notes.wayneh.tw 和 Pro，第二個 commit 才能開始寫出新格式。 下面有 12 個要你決定的問題，每個都附了建議。

完整文件：design.md（做法、介面、測試、分期）、decision.md（決策表）。

一、資料長什麼樣

每個 Focus 只有一棵樹。 節點有兩種：窗格（有 id、放 tab）和分割（有 id、方向、兩個以上的子節點）。 窗格的編號依樹的順序（由左到右、由上到下）排，舊劃分轉過來的編號跟原本一樣。

左大右二（舊）             轉成的樹（新檔 version 2）
+------+------+            split major-left  橫向
|      |  p2  |              +- pane p1
|  p1  +------+              +- split major-left-1  直向
|      |  p3  |                   +- pane p2
+------+------+                   +- pane p3
  • 上限（建議）：每個 Focus 最多 8 個窗格、分割最多巢狀 4 層；tab 總數照舊最多 100。
  • 同方向的分割會自動攤平（左右分割裡再切左右，就變成三欄），跟 Obsidian 一樣。
  • 窗格和分割有固定的 id，所以裝置上記住的「作用窗格、顯示哪個 tab、分隔線位置」不會因為別處切開或收起而錯位。

二、舊檔與兩個部署的時間差

這是最需要注意的地方。 舊版程式讀到 version 2 的 Focus 檔，不只 Focus 打不開，那個儲存庫裡所有筆記與資料夾的搬移都會被拒絕（422「Fix the file before moving content」）。 notes.wayneh.tw 和 Pro 用同一份 core，但部署時間不同，所以有一段時間會有一邊是舊版。

做法：新程式讀 version 1 時，一律轉成同一棵樹、同一組 id（不能用亂數，不然遠端提交會一直誤報衝突）。 寫回時，只要每個 Focus 都還是舊劃分的形狀，就照舊寫 version 1；只有真的切出舊劃分表達不了的形狀，才寫 version 2。 第一個 commit 的介面還切不出新形狀，所以它只會寫 version 1。

phase 1  新讀取器 + 仍寫 v1   --> 部署到 notes.wayneh.tw 與 Pro
                                  （你確認 Pro 已更新）
phase 2  拖到邊緣分割          --> 開始可能寫出 v2
phase 6  永遠寫 v2             --> 你說兩邊都已過 phase 1 才做

暫存 Focus 存在各網域自己的瀏覽器裡，兩個部署不共用，所以不受影響。

三、分期

#內容使用者看得到的改變
1core 改成分割樹；讀 v1、仍寫 v1；網頁改用窗格 id幾乎沒有；平板上 2×2 改成上下兩列（見 D8）
2拖到窗格邊緣分割、關最後一個 tab 收起窗格可以自由分割
3「劃分」選單換成「向右分割、向下分割、合併所有窗格」；命令面板、加入 Focus 對話框的窗格圖不再有劃分預設
4只有一個窗格時，「開在旁邊」改成向右分割合輯卡片開在右邊（D9，你可以不要）
5文件與用語表無
6拿掉 v1 寫入無（要等你確認）

MCP server 沒有 Focus 相關程式；local server 只透過共用的工作區文件路由讀寫，路由不用改；Pro 在 core 之外沒有用到 Focus，只需更新 submodule。

四、要你決定的事

#問題建議另一個選擇
D1上限最多 8 窗格、4 層分割；到上限時邊緣不能放、分割命令停用不設上限（窗格可能小到不能用）
D2分隔線位置存哪裡存在各裝置（跟現在一樣）存進 Focus 檔：每台裝置看起來一樣，但每次拖分隔線都會產生一筆待提交的變更
D3拖放區域窗格內容區外圍四分之一是邊緣（分割），其餘是中央（加成 tab）；tab 列只排序不分割；拖 tab 到邊緣是移動，按 Shift 是複製；顯示預覽陰影邊緣區更窄（例如固定 60px）
D4空窗格只在關掉或拖走最後一個 tab 時收起；其他空窗格（舊劃分留下的、筆記被刪的）顯示「關閉窗格」按鈕；最外層那一格永遠不收載入時自動清掉空窗格
D5「劃分」選單變成什麼「向右分割、向下分割、合併所有窗格」，拿掉七種預設保留預設當作「重排成…」捷徑
D6向右／向下分割時，新窗格放什麼再開一份目前顯示的筆記（Obsidian 的做法），新窗格成為作用窗格新窗格是空的
D7命令面板拿掉七個劃分命令，加「向右分割、向下分割、合併所有窗格、關閉空窗格」，都不綁預設按鍵；上一個／下一個窗格依樹的順序另加方向鍵移到左右上下的窗格（本次不做）
D8窄螢幕桌機顯示整棵樹；平板依最外層分割分成兩半；手機一格裝全部 tab；邊緣分割只在桌機平板維持「第一格單獨、其餘合併」
D9只有一個窗格時「開在旁邊」桌機上向右分割（合輯卡片不再蓋住合輯）；[[連結]] 仍開在同一格維持現在：開成同一格的新 tab
D10加入 Focus 對話框依樹畫窗格縮圖，每格一個選項，方向鍵依序切換；對話框裡不提供「新分割」對話框也能選「放到新的右側窗格」
D11跨部署上線如第二節：phase 1 兩邊都部署後才上 phase 2；v1 寫入等你確認後才拿掉直接寫 v2，接受舊部署暫時不能搬移筆記
D12用語停用「劃分」；動作叫「分割」（向右分割、向下分割、合併所有窗格、關閉窗格）；整體需要命名時叫「窗格配置」沿用「劃分」指整體配置

五、已知風險

  • 切開窗格時，被包進新分割的那格編輯器會重新掛載，捲動位置與復原紀錄會消失（現在換劃分也是這樣）；先存檔再切，不會掉內容。
  • Phase 1 改動面大（所有用窗格編號的地方都換成 id），但行為不變，現有測試就是它的檢查點。
  • 同一個瀏覽器網域如果退回舊版，該裝置的暫存 Focus 會變空；具名 Focus 不受影響。
